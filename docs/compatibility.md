# Compatibility and verification

This file records evidence, not a general compatibility guarantee. Checked 27 October 2026.

- Node 24.22.1 on macOS arm64 is the current local test runtime. The system Node installation is unchanged.
- Readest 0.12.16 is installed on this Mac. Local fixtures follow its `library.json`, managed book directories and per-book configuration. Passive reads do not launch the app or modify its data.
- Cloud fixtures follow Readest snapshot `44c90152f6b04e74f71245bb3642d9a7e03042ed`: raw DB records from separate books/configs/notes pulls, book `synced_at` pagination and note/config update/deletion clocks. This is a published application interface, not a guaranteed versioned developer API.
- Authentication follows the official KOReader integration's separate email/password session. Social-only accounts may require setting a password in Readest. This MCP never does that on the user's behalf and never imports the reader's session automatically.
- Default cloud project configuration is the vendor-published anonymous project URL/key from that snapshot's `.env`. Its JWT role was checked as `anon`; it is public project configuration, not an account session or service-role credential. Account sessions stay in private local storage.
- The cloud factory resolves the session's account identity before choosing its cache partition. Changing the account requires reconnecting the MCP, preventing previous-account cache reuse.
- Download requests use the account-qualified key `{userId}/Readest/Books/{bookHash}/{bookHash}.{ext}` required by Readest's parser and hash/extension fallback. A live file probe exposed the previously incomplete key; strict synthetic EPUB/PDF regressions now reject it. Account authorization is not forwarded to storage downloads.

Sources: [sync documentation](https://www.readest.com/docs/sync), [sync server](https://github.com/readest/readest/blob/44c90152f6b04e74f71245bb3642d9a7e03042ed/apps/readest-app/src/pages/api/sync.ts), [download endpoint](https://github.com/readest/readest/blob/44c90152f6b04e74f71245bb3642d9a7e03042ed/apps/readest-app/src/pages/api/storage/download.ts), [KOReader authentication](https://github.com/readest/readest/blob/44c90152f6b04e74f71245bb3642d9a7e03042ed/apps/readest.koplugin/readest_supabaseauth.lua).
## Fixture and installation checks

- 76 default tests passed on macOS arm64: all six real MCP tools in local and loopback-cloud processes, identical definitions, exact-reference retrieval, long chapter continuation, stale editions, missing versus empty notes, cloud timeouts with/without cache, content limits and private path/session boundaries. Nine additional regressions from the whole-branch review/author pass were observed failing before their fixes: mixed PDF gaps, vector coverage beyond 50 books and by target, context-edition continuation, offloaded text freshness, empty cached cloud results, long notebook summaries, operation-specific warnings content continuation beyond one million characters, and account changes within the metadata reuse window.
- A packed production-only install in a clean directory passed initialization, tool discovery, EPUB extraction/search and an exact-reference round trip with optional dependencies omitted. A separate installed package with optional dependencies passed real local-model inference.
- Production dependency audit reported no known vulnerabilities at the check time. Dependency licenses were inspected; the model is downloaded separately.
- Readest 0.12.16 was rechecked on this Mac. No saved library was found in the bounded standard local paths. No live local library or Drive sync was tested.
- Separate cloud sign-in, authenticated catalogue reads and forced session renewal succeeded. A subsequent owner-authorized import exercised 25 EPUBs and one PDF: all 26 cloud downloads matched the selected source fingerprints, all 26 were indexed, and each passed a structure-to-passage reference round trip through the real SDK/client. The PDF reported known text gaps with partial coverage. Annotation lists were empty on these newly imported books, so saved-highlight retrieval remains unverified on real annotations. Personal books/text are not included in this repository. The private session file remained 0600; no browser/app token was extracted and no password was stored.
- A fresh local Codex app-server client discovered all six tools and successfully called library_status against the authorized cloud account, using an ephemeral diagnostic session rather than a saved chat. Prior client settings were preserved. Current-chat reconnection has not been demonstrated; the running app's optional control socket was unavailable, so an existing chat may need reopening.
- [GitHub CI passed](https://github.com/gbettineschi/readest-mcp/actions/runs/40520052706) on Node 24/macOS, Linux and Windows for code commit cff7a1e, including typecheck, all 76 default fixture/package tests, build and package checks. Real-model and live-account tests remain opt-in and were run separately on this Mac. Windows PDF resource paths and npm spawning were corrected from actual runner failures before this passing run.

## Local semantic retrieval probe

On this arm64 Mac with Node 24.22.1, Transformers.js 4.3.1 and the pinned q8 multilingual E5-small model, the opt-in offline CPU test retrieved all six predetermined English/Italian paraphrases within the top three of eight synthetic passages. Vectors were finite, 384-dimensional and normalized. One warm-filesystem run took 1.15 seconds including model initialization, with process peak RSS 689.75 MiB (the test runner is included). This is a small corpus/host measurement, not a library-scale performance claim. Model files total about 140 MB and are explicitly downloaded, checksum-verified and kept outside the repository.


## Larger local retrieval probe

The authorized 26-book corpus produced 49,337 evidence passages and 49,693 local embedding chunks. Keyword and hybrid queries retrieved useful source passages; an English semantic paraphrase over English books also did. An Italian paraphrase across the mixed corpus returned weak cross-language rankings, including short headings. Persisted vectors exactly matched recomputed embeddings in a sampled check, ruling out storage corruption for that sample. This is an observed retrieval-quality limitation, not a claim of reliable multilingual relevance at library scale. Trying the book’s language or narrowing book filters can help; a reranker or different chunking/model is not part of this version.
